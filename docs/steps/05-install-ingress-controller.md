# Шаг 5. Установка NGINX Ingress Controller

Скрипт: `scripts/05-install-ingress-controller.sh`

## Назначение

Установить `ingress-nginx`, чтобы маршрутизировать внешний HTTP/HTTPS трафик по Ingress-правилам. Сервис контроллера публикуется как `LoadBalancer`, адрес выдает `MetalLB`.

## Предварительные условия

- выполнены шаги 0-3: VM, Kubernetes, `Flannel`, `MetalLB`;
- на хосте доступен `multipass`;
- мастер-нода называется `k8s-master`.

Шаг 4 (`ArgoCD`) для установки контроллера не обязателен. Он нужен только если сразу после этого настраивается Ingress для `ArgoCD`.

## Что делает скрипт

1. Применяет манифест `ingress-nginx` версии `controller-v1.12.1` для cloud-провайдера. В локальном стенде роль внешнего балансировщика выполняет `MetalLB`.
2. Ждет, пока все pod'ы в namespace `ingress-nginx` перейдут в `Running`.
3. Читает внешний IP сервиса `ingress-nginx-controller`.

## Результат

В кластере появляется Ingress-контроллер класса `nginx`. Скрипт печатает IP-адрес, который нужно использовать для доступа к сервисам через Ingress.

Этот IP позже добавляется в файл `hosts` Windows для имени `argocd.local` (шаг 6).

## Важные замечания

- версия контроллера зафиксирована: `controller-v1.12.1`;
- манифест берется из upstream, локальной копии в `manifests/` нет;
- ожидание готовности считает pod'ы в статусе `Running`, но не проверяет `Ready`;
- если `MetalLB` еще не выдал адрес, IP в выводе может быть пустым.
