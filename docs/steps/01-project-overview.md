# Обзор проекта

## Назначение

Проект `k8s-platform` - это учебный стенд для поэтапного развертывания локального Kubernetes-кластера и дальнейшей настройки базовых платформенных компонентов.

Главная задача проекта - не просто поднять кластер, а последовательно понять:
- как создаются и подготавливаются узлы;
- как инициализируется control plane;
- как подключаются worker-ноды;
- как настраивается сеть Pod и внешняя публикация сервисов;
- как поверх базового кластера добавляются платформенные сервисы.

## Текущий контекст

Сейчас проект находится на этапе настройки платформенных компонентов поверх базового кластера. Уже выполнены:
- создание виртуальных машин в `Multipass`;
- установка `containerd`, `kubeadm`, `kubelet`, `kubectl`;
- инициализация кластера;
- установка сетевого плагина `Flannel`;
- установка `MetalLB`;
- создание манифеста или конфигурации IP-пула для сервисов типа `LoadBalancer`;
- установка `ArgoCD`;
- установка `NGINX Ingress Controller`;
- публикация UI `ArgoCD` через Ingress на `argocd.local`;
- преднастройка GitOps: репозиторий `argocd-apps` и Application `nginx`;
- черновик IaC в `terraform/` и рабочий стек OpenTofu в `opentofu/`.

Ближайшая работа: связка с GitLab CI/CD. После этого - `RBAC` и `HashiCorp Vault`.

## Базовая архитектура стенда

На текущем этапе используется локальный стенд из трех виртуальных машин:
- `k8s-master` - control plane;
- `k8s-worker1` - первая worker-нода;
- `k8s-worker2` - вторая worker-нода.

Сетевой уровень построен на:
- `Flannel` для внутренней Pod-сети;
- `MetalLB` для выделения внешних IP-адресов сервисам;
- `ingress-nginx` для маршрутизации внешнего трафика по Ingress-правилам.

Платформенный слой на текущем этапе:
- `ArgoCD` в namespace `argocd`;
- Ingress `argocd-ingress` для доступа по имени `argocd.local`;
- GitOps: репозиторий `https://github.com/brooh2121/argocd-apps.git` и Application `nginx`.

## Принцип работы репозитория

Репозиторий организован по шагам:
- каждый скрипт в `scripts/` отвечает за отдельный этап;
- скрипты для провижининга через OpenTofu лежат в `scripts-tofu/`;
- IaC лежит в `opentofu/` (основной путь) и `terraform/` (ранний эксперимент);
- манифесты Kubernetes лежат в `manifests/`;
- документация bash-шагов хранится в `docs/steps/`;
- документация OpenTofu и Terraform хранится в `docs/terraform/`.

Такой подход позволяет развивать проект итеративно: сначала поднять кластер вручную и понять его устройство, а затем объединить шаги в единый автоматизированный пайплайн.
